# 코드 이슈 검토와 개선 방향

현재 남아 있는 이슈와 수정 방향을 정리한다. 완료된 이슈는 이 목록에서 제외하며, 현재 구현과 검증 범위는 [구현 현황](08-current-implementation.md) 및 [검증 계획](04-development-plan.md)을 참고한다. 이슈 번호는 검토 대상의 번호다.

## 판단 기준과 우선순위

- **PoC 수정**: 잘못된 근거·검색 결과, 되돌리기 어려운 중복 비용, 실제와 다른 상태 안내를 막는 데 필요한 범위.
- **검증 후 결정**: 문제가 발생할 조건이나 해결 방법의 효과를 대표 문서·질의로 확인해야 하는 항목.
- **TODO**: PoC가 단일 서버·제한된 데이터와 사용자로 동작한다는 전제에서 미룰 수 있는 확장·운영 개선. 이 전제가 달라지면 우선순위를 다시 정한다.
- **부분 타당**: 현상은 존재하지만 제안된 원인, 영향 또는 해결 방법을 그대로 받아들일 수 없다.

### PoC 수정 순서

1. **게시 버전과 작업 안전성**: 4-4의 게시 상태 복구 → 4-5. 기존 검색 결과와 근거가 서로 다른 상태를 가장 먼저 막는다.
2. **누락과 사용자 상태**: 4-6. 미확인 페이지를 정상으로 단정하지 않고 실제 처리·게시 범위를 표시한다.
3. **검색 품질 평가**: 한국어 질의셋으로 BM25·Dense·Hybrid와 제목 계층 추정의 정확도를 평가한다.

실환경 연결 확인과 실제 문서·질의에 대한 품질 평가는 별도로 수행한다.

## 항목별 판정

### 파싱·누락 확인

**3-5. 전체 재파싱 결과 선택 — 부분 타당 / TODO.** [병합](../../packages/indexer/src/indexer/parse_workflow.py)은 기존 정상 페이지를 유지하고 누락 페이지 복구에 초점을 둔다. 전체 재파싱 결과를 버리는 비용 문제는 있으나, 새 결과가 더 정확하다고 보장되지 않으므로 무조건 교체하거나 ‘더 좋은 결과’를 자동 선택해서는 안 된다. 먼저 실제 문서에서 페이지별 원문·구조 차이와 비용을 평가하고, 필요할 때 기존/새 결과 비교와 사용자 선택을 설계한다.

**2-4. 배치 다운로드 중 전체 기한 — 타당 / TODO.** 반복문 밖 경계에서만 기한을 확인하므로 여러 다운로드가 누적되면 설정된 전체 시간보다 오래 걸릴 수 있다. 남은 기한을 각 요청에 적용하고 받은 배치를 보존한다. 대형 문서 시연이 필수라면 PoC 수정으로 올린다.

**3-1. 재시도 도중 서버 중단 — 부분 타당 / TODO.** 동기 재요청의 결과나 접수 여부를 복구할 수 없는 문제는 있다. 다만 최초 파싱 산출물은 저장되므로 항상 ‘처음부터 파싱해야 한다’고 단정할 수 없다. 저장된 원본 결과에서 검색 준비가 가능한 조건을 검증해 안내하고, 접수 불명 요청을 자동으로 다시 보내지 않는다. 서버 중단 복구 시나리오는 별도 테스트한다.

**3-3. 저장된 재시도 계획 고정 — 부분 타당 / TODO.** 같은 요청이 다시 과금되는 것을 막기 위한 고정 계획 자체는 합리적이다. 재개 중 새 누락이 확인되어도 추가 자동 재시도가 없다는 제한은 명시한다. 이후 확정된 누락에 대한 별도 시도 ID와 사용자 승인, 시도별 결과·비용 기록을 설계한다. 접수 불명과 확정 실패는 분리한다.

### 게시·상태·동시성

**4-3. 다른 문서 게시로 적용 거절 — 타당 / TODO.** 현재는 비교 당시의 전체 인덱스 버전이 바뀌면 거절한다. 안전하지만 다른 문서 변경도 충돌로 취급한다. 해당 문서의 적용 대상 청크·작업 스냅샷이 바뀌었는지 확인하는 방식으로 개선하되, 동시 삭제·같은 문서 변경·모델 프로필 차이는 충돌로 유지한다. 지금도 재처리 없이 재검토할 수 있는 별도 경로가 있는지는 구현 시 확인한다.

**4-4. 색인 재개와 적용 직후 중단 — 타당 / 게시 상태 복구는 PoC 수정, 비동기화는 TODO.** 적용 게시와 작업 상태 저장 사이에 중단되면 실제 활성 버전과 화면 상태가 달라질 수 있다. 게시된 manifest와 작업·청크 식별자를 대조해 이미 적용된 작업을 안전하게 완료 처리하고, 그 사이 다른 변경이 있으면 자동 덮어쓰지 않는다. 색인 재개를 요청에서 분리하는 장기 작업 구조는 TODO이나 시연 중 응답 대기와 재클릭을 안내한다.

**4-5. 삭제 대기 문서의 재개 — 타당 / PoC 수정.** UI뿐 아니라 서버의 모든 재개·재처리 진입점에서 삭제 대기 상태를 검사해 외부 호출 전에 거부한다. 삭제와 재개의 경합도 확인한다.

**4-6. 청크가 없는 부분 결과 — 타당 / PoC 수정.** 게시된 검색 내용이 없을 때 ‘검색에 반영’이라고 안내하지 않는다. 검색 가능 청크 수, 실제 게시 여부, 기존 버전 유지 여부와 누락 상태를 별도로 표시한다. 확인된 빈 문서와 파싱 실패를 모두 같은 오류로 취급하지 않는다.

**0-1. 작업 전체 잠금 — 타당 / TODO.** 워커의 파싱부터 게시까지 공용 작업 잠금이 유지되어 업로드·삭제 등 변경 요청이 대기한다. 단일 사용자 PoC에서 작업 중 대기를 명시하고, 다중 사용자 처리 요구가 생기면 외부 호출과 짧은 상태 전이 잠금을 분리한다. 잠금 축소 시 작업별 상태 및 게시 경합 방지가 선행돼야 한다.

**0-3. 큐 순서와 워커 종료 — 부분 타당 / TODO.** 문서 목록은 디렉터리 순회를 사용하므로 UUID순이라고 보장되지 않으며, 문서 안에서는 최신 작업부터 확인한다. 저장 오류 등이 워커를 종료시킬 가능성은 있다. FIFO가 필요하면 생성 시각과 안정적 tie-breaker를 정하고, 예외 기록·워커 생존·장애 상태 표시를 검증한다. PoC에서는 단일 작업 위주로 운용한다.

**0-4. 동기 재구축 — 타당 / TODO.** 대기 후 전체 재구축 중 요청이 끊기면 사용자가 완료 여부를 혼동할 수 있다. 캐시가 있어 매번 모든 임베딩 비용이 반드시 반복되는 것은 아니다. 상태가 있는 비동기 작업과 중복 요청 방지를 향후 도입하고, 현재는 재구축 중 재요청을 피하도록 안내한다.

### 청킹·출처

**5-12. 미사용 코드 — 대체로 타당 / TODO.** 실제 호출 경로와 테스트 전용 코드를 구분해 정리한다. `inspection.inspect`는 HWP/HWPX 검사에 사용되고, `table_continuity`의 일부 보조 함수도 사용 중이다. 모듈 전체를 지우지 않는다. 문서가 실제 호출을 과장하는 곳도 함께 고친다.

### 임베딩·검색·대화

**7-7. 청크 파일 이중 읽기 — 타당 / TODO.** 검색과 근거 조회는 삭제와 경합하지 않도록 보호되지만 청크 파일은 두 번 읽는다. 검색에 필요한 청크 스냅샷을 재사용해 불필요한 파일 읽기를 줄인다.

### 규모·비용·운영

**5-10. 표현 버전 일괄 반영 — 타당 / TODO.** 기존 작업의 파싱 결과를 활용해 표현 버전별 대상 조회, 일괄 재청킹, 새 검색 버전 게시 및 실패 재개를 제공한다. 원본 파싱을 자동 재호출하지 않으며, 결과 비교와 보존 정책을 함께 설계한다.

**6-1. 검색 버전·작업 누적 — 타당 / TODO.** 버전마다 컬렉션과 로컬 산출물이 누적되며 과거 버전 참조 때문에 작업과 모델 삭제가 제한된다. 보존 기간·수량, 명시적 삭제, 활성 버전과 참조 중 작업 보호를 설계한다. PoC에서도 저장 공간은 관찰한다.

**6-2. 문서 삭제 시 임베딩 캐시 — 타당 / TODO.** 캐시 전체 삭제로 이후 게시 시 다른 문서도 재임베딩할 수 있다. 캐시 키별 참조 또는 안전한 선택 삭제를 고려한다. 다른 버전이 공유하는 벡터를 성급히 지우지 않는다.

**6-3. 기본 모델 계약 변경 — 타당 / TODO.** 연결 주소 등을 포함한 계약이 바뀌면 기존 벡터와의 혼합을 막기 위해 재구축이 요구된다. 주소만의 변경이 같은 모델 공간인지 자동으로 확신할 수 없으므로 계약 검사를 없애지 않는다. 새 프로필을 만들고 새 색인을 준비한 뒤 전환하는 흐름과 비용을 안내한다. 안전한 동일성 확인 방법은 별도 검증한다.

**6-5. 추가 모델 색인 상태·진행 — 부분 구현 / TODO.** 설정에서 선택한 모델의 기존 색인을 수동 재구축할 수 있다. 프로필별 상세 상태, 비동기 진행 및 실패 복구는 추가로 설계한다. 모델 간 벡터 혼합을 막고 비용과 완료 전 검색 가능 여부를 표시한다.

## 검증 범위와 남은 확인

- 미해결 이슈는 코드 경로와 자동 테스트, 한국어 검색의 SQLite 재현을 토대로 판단했다. 실제 외부 파서·임베딩·원격 Qdrant 연결이나 유료 호출은 검증하지 않았다.
- 남은 수정의 회귀 검증에는 중단 후 게시 상태 복구, 0청크 안내, 삭제 대기 재개를 포함한다. 청킹·검색·대화와 기존 작업 재개에 대한 자동 테스트도 유지한다.
- 검색 품질은 대표 한국어 문서와 정답 근거를 가진 질의로 BM25·Dense·Hybrid의 검색률과 인용 정확도를 측정한다. 임베딩 모델·청크 크기·겹침과 n-gram 방식의 우열은 실험 전 확정하지 않는다.
