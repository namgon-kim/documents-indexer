# 구현 현황과 한계

| 기능 | 현재 동작 |
|---|---|
| 입력 | PDF, HWP, HWPX, DOCX, XLSX, PPTX. 시그니처·크기, HWP 암호·헤더 및 HWPX·Office 압축 구조 검사. 동일 파일은 기존 문서 안내 후 명시적으로 중복 등록 가능 |
| 파싱 | Upstage·PaddleOCR-VL 어댑터와 HWP/HWPX/DOCX/XLSX/PPTX 직접 추출. 삽입 이미지 원본을 보존하고 별도 분석 선택 가능; 처리하지 못한 범위는 경고와 일부 처리 상태로 표시 |
| 누락 | PDF 확정 누락의 50% 기준 부분·전체 재파싱; 미수신 결과는 기존 요청 조회. 빈 페이지, 텍스트 없는 그림 및 원격 미완료 상태 구분 |
| 청킹 | 제목 경로, 본문·목록, 표 셀, 캡션·인접 관계, 원문 요소 참조. 표현 버전 `structure-v13`. 반복 머리글·바닥글과 확인된 페이지 번호는 제외 사유를 기록; 추정 제목 계층은 표시 |
| 임베딩 | 문서·질의 모델과 차원별 프로필, 바이트·배치 설정, 명확한 길이 초과 시 분할, 캐시 |
| 색인·검색 | 프로필별 Qdrant와 SQLite BM25, 어절·부분 문자열 검색, 검색 버전, Dense/BM25/Hybrid 및 선택적 재순위 |
| 대화 | 동일 검색 경로와 버전·범위, Chat Completions API 답변, 근거·문맥 링크와 번호 |
| 재처리 | 파싱부터 또는 저장된 파싱 결과부터; 감소 감지 시 기존 색인 유지 및 사용자 비교 |
| 웹 | 문서 관리·진행 단계·검색·대화·설정. `/embed` 삽입 인증 지원 |

PDF의 확정 누락이 전체 페이지의 절반 이하면 해당 페이지만, 절반 초과면 전체를 다시 읽는다. 미수신 결과는 별도이며 기존 요청에서 조회한다. 확정 누락이 절반을 초과하는 동시에 미수신 결과가 있으면 전체 재요청을 보류한다. 재시도 결과와 접수 기록을 보관해 확인된 작업을 중복 제출하지 않는다. 이미 게시된 작업의 파싱 재개는 새 작업으로 분기해 기존 근거를 유지한다. 종료·취소된 원격 작업이 더 제공하지 않는 페이지는 자동 재개하지 않으며, 완료 배치의 일시적 다운로드 실패는 재개할 수 있다. 실제 가능한 재시도는 페이지 한도와 파서 지원에 좌우된다.

현재 표현은 같은 페이지·제목의 본문을 묶고 검색 시 인접 본문을 앞뒤 최대 600자씩 확장한다. 캡션·표 이어짐과 제목 번호로 추정한 계층은 추정으로 표시한다. 근거 페이지와 문맥 페이지를 구분한다. 작업 상세의 검색 표현 점검은 누락 후보와 제목·캡션 문맥의 축약을 표시하며 의미적 완전성을 보장하지 않는다. 캡션이 표·그림 검색 문맥에 온전히 포함되지 않으면 별도 청크를 유지한다. 재분할 출처를 정확히 좁힐 수 없는 경우 확인 필요로 표시한다. 재처리 비교는 단어·셀·행 관계를 보수적으로 확인하며 의미적 일치나 원본 누락이 없음을 보장하지 않는다.

임베딩 입력 바이트는 모델의 토큰 한도가 아닌 사용자 설정 안전 한도다. 서버 기본 모델에는 환경 변수 또는 서버 설정을 적용하고, 별도 모델에는 등록된 한도를 적용한다. 새 모델의 화면에서는 값을 직접 입력하며, API에서 값을 생략하거나 서버 기본값을 설정하지 않으면 3,800바이트를 사용한다. 모델의 토큰 한도를 추측하지 않으며, 명확한 공급자 길이 오류에 한해 입력을 나눈다. 설정 변경은 이미 생성된 청크를 자동으로 다시 만들지 않으므로 청크 크기를 변경하려면 재청킹이 필요하다. 인증·요청 한도 등 다른 오류는 분할하지 않는다. `PARSER_PROVIDER`를 비우면 처리 및 검색 서비스가 초기화되지 않는다. `ALLOW_EXTERNAL_PROCESSING=0`이면 초기화된 색인의 BM25만 외부 호출 없이 사용할 수 있다.

청크 크기와 겹침 기본값은 문자 수로 범용 1000/150, 보고서 1200/200, 매뉴얼 800/100, 스캔본 1200/200, 스프레드시트 1500/0, 슬라이드 1000/100이다. 자동 선택은 XLSX를 스프레드시트, PPTX를 슬라이드, 나머지를 범용으로 선택한다. 범용 값은 서버 설정 또는 환경 변수로 변경할 수 있다. 유형을 바꾸면 기본값이 다시 적용되며 이후 직접 변경할 수 있다. 기존 환경 변수와 기존 작업의 설정은 유지된다. 설정값은 목표 크기이며 문서 구조와 임베딩 입력 바이트 제한에 따라 실제 청크 크기는 달라진다.

XLSX 직접 추출은 차트가 있으면 LibreOffice와 `pdftoppm`으로 차트 주변 시트 영역을 렌더링해 미리보기를 생성한다. 저장된 참조 이미지는 원본 차트 객체가 아니며 글꼴·레이아웃·데이터 표시가 원본과 다르거나 주변 셀을 포함할 수 있다. 검토 및 검색 결과에서도 미리보기로 구분한다. 렌더러가 없거나 실패한 차트는 시트와 위치를 경고하고 확인 대기한다. 컨테이너에는 렌더러와 한국어 글꼴을 설치한다. 로컬 실행에는 LibreOffice와 Poppler가 별도로 필요하다. 기존 파싱 결과에 차트를 추가하려면 문서를 다시 읽어야 한다.

PaddleOCR-VL로 개별 이미지를 분석할 때는 별도 지정이 없으면 이미지 블록 OCR과 차트 인식 옵션을 켠다. 파서 옵션에서 명시한 값은 우선하며 PDF 전체 파싱 요청의 설정은 변경하지 않는다. OCR 옵션을 켜도 추출 품질은 공급자 응답에 따라 달라진다.

Excel/PPT의 파서 페이지와 원본 위치는 자동으로 동일시하지 않는다. XLSX 직접 추출은 영역의 시트·범위, 청크별 원본 셀 주소와 이미지의 앵커 셀을 기록한다. HWPX는 섹션 단위, HWP 직접 추출은 구역·문단 단위 출처를 사용한다. HWP 이미지의 원본 문단 참조가 없으면 위치 미확인으로 보존한다. 도형 관계 추출은 없다. LangGraph 상태 자체는 영속 체크포인터로 저장하지 않으며 파일에 기록된 요청·산출물과 임베딩 캐시로 복구한다. 실제 문서별 OCR·검색 품질과 서비스 연동은 자동 테스트 결과만으로 입증되지 않는다. 원격 결과 만료의 세부 응답은 공급자·프록시 계약 확인이 필요하다.

텍스트 없는 그림은 빈 페이지로 간주하지 않는다. 누락 확인이 필요한 결과는 신규 문서도 게시 전 검토 상태로 둔다. 이미지별 선택은 같은 미게시 작업에 반영하며, 미처리 이미지나 누락 등 확인할 사항이 더 이상 없으면 자동 게시한다. 중첩 표를 별도 표로 추출해 상위 셀과의 관계가 보존되지 않는 것은 처리 한계로 표시한다. 이미 게시된 작업은 새 작업으로 분기한다. 사용자가 직접 작성한 단독 이미지 설명은 검색 텍스트이며 원본 이미지에 연결된다. 원격 작업 상태 조회의 일시적인 오류는 제한적으로 재시도한다. 확정 거절과 접수 불명 오류는 구분하며 접수 불명은 자동 재전송하지 않는다.

파서와 임베딩의 HTTP 오류는 작업 상태와 JSON 로그에 상태 코드를 기록하고, 코드별 확인 안내를 제공한다. 임베딩 403 응답에서 크레딧 부족이 명시된 경우 결제·크레딧 확인을 안내한다. 응답 본문과 인증 정보는 로그에 기록하지 않는다.

검색용 텍스트와 질의는 NFC로 정규화하며 이 전처리 버전은 임베딩 계약에 포함된다. 이전 계약의 검색 버전은 BM25로 유지하고 Dense·Hybrid 사용에는 선택 모델의 색인을 다시 준비해야 한다. 재구축에는 임베딩 비용이 발생할 수 있다. 기존 작업 원본은 유지되며 재구축만으로 이전 문서가 새 청킹 방식으로 바뀌지는 않는다.

표 열 제목 추정과 동일 원본 표의 제한적 검색 확장 계약은 [처리 흐름](01-architecture-pipeline.md)을 따른다. 검색 확장은 기존 색인에도 적용되지만, 새 열 제목 표현은 기존 파싱 결과부터 다시 청킹·임베딩해 새 검색 버전을 게시해야 반영된다. 기존 버전은 그대로 검색할 수 있다.

HWP/HWPX는 변환 페이지 수를 사전에 알 수 없어 비동기로 접수한다. 공급자가 반환한 페이지 수와 배치 누락은 원본 쪽 수의 검증값이 아니며, 부분 결과는 기존 검색을 보호하고 미수신 배치는 같은 요청 ID로 재조회한다.

부분 문자열 색인이 있는 BM25 검색은 일반 토큰·부분 문자열·짧은 접두어 후보를 각각 검색해 질의어 일치 범위와 순위 융합으로 결합한다. 서로 다른 토크나이저의 BM25 원점수는 합산하지 않는다. 반환 점수와 순서는 기존 이어붙이기 방식과 달라질 수 있다. 부분 문자열 색인이 없는 이전 버전은 기존 일반 토큰 검색을 유지하며, 검색 시 색인을 재구축하거나 외부 모델을 추가 호출하지 않는다.

일치 범위는 검색된 제한된 후보에 대해 메모리 임시 FTS 색인을 만들고 동일한 `unicode61`·`trigram` 규칙으로 계산한다. 원본 텍스트와 게시된 색인에는 정규화 변경을 적용하지 않는다.

도식의 `figure-structure-v4` 검색 표현은 파서 HTML과 텍스트에서 확인된 동일 문구를 중복 결합하지 않으며, 파서가 넣은 이미지 자리표시만 검색에서 제거한다. 양쪽에만 있는 내용과 원본 파서 산출물은 보존한다. 분할 조각의 `normalized_element_text` 범위는 정규화된 요소 텍스트의 문자 오프셋이며 원본 PDF 좌표나 원시 파서 텍스트 오프셋이 아니다. 새 표현과 경계는 재청킹한 새 작업에 적용되고 기존 게시 색인은 유지된다.

게시 버전에는 활성 포인터의 이전 버전 연결과 승인 게시 식별자를 기록한다. 새 형식의 버전은 활성 포인터에서 연결되는 경우에만 게시된 버전으로 취급하며, 승인 후 상태 저장이 중단되면 게시 식별자와 작업 출처를 확인해 상태를 복원한다. 이전 형식의 연결되지 않은 버전은 게시 이력을 확정할 수 없어 `legacy_unknown`으로 표시하고 검색 호환성을 유지하며 해당 작업은 삭제하지 못하도록 보호한다. 서버 시작 시 새 형식의 미게시 빌드 마커 또는 매니페스트를 확인해 활성 이력에서 참조되지 않는 디렉터리와 컬렉션을 정리한다. 정리 실패 시 파일을 남겨 다음 시작에 재시도한다. 레거시 이력이 불명확한 버전은 정리하지 않는다.

메타데이터 JSON은 임시 파일과 디렉터리를 fsync한 뒤 사용한다. 이것은 파일 단위 내구성을 보강하며 Qdrant와 여러 파일 사이에 원자적 트랜잭션을 제공하지 않는다. 임베딩 캐시는 모델 계약과 원문 해시를 기반으로 공유되므로 문서 삭제 시 전체 캐시를 삭제하지 않는다. 삭제 문서의 벡터도 공유 여부를 구분할 수 없어 캐시에 남으며, 캐시 삭제·보존 정책은 별도 운영 결정이 필요하다. 파서의 장문 접수·조회·다운로드에는 남은 처리 시간을 요청 타임아웃으로 적용한다. HTTP 타임아웃은 공급자와 전송 계층의 지연을 완전한 벽시계 기한으로 보장하지 않는다.

`/health`는 API liveness와 별도로 워커 상태 및 연속 오류 횟수를 제공한다. 워커의 예기치 않은 오류는 기록하고 지수 백오프로 다시 확인한다. 워커 및 동기 업로드는 전역 잠금 안에서 작업을 예약하고 외부 파싱·임베딩은 잠금 밖에서 수행한다. 실행 중인 문서의 삭제 및 충돌 작업을 제한한다. 파이프라인 설정 변경과 파서 프로필 활성화는 워커·동기 업로드가 점유한 작업, 문서 예약, 재구축과 저장된 `processing` 작업이 모두 없을 때만 허용하고 그 밖에는 409 `JOB_IN_PROGRESS`로 거부한다. 승인 게시와 색인 재개는 문서별 예약을 사용하며 외부 호출 중 전역 작업 잠금을 놓는다. 전체 재구축은 모든 게시 문서로 활성 색인을 다시 만드므로 다른 색인 변경과 배타적으로 실행한다. 점유·예약·처리 중인 작업이 있으면 시작을 거부하고(`REBUILD_UNAVAILABLE`), 진행 중에는 동기 업로드(`INDEX_REBUILD_IN_PROGRESS`), 승인 게시·색인 재개·문서 삭제를 409로 거부한다. 대기열 업로드는 접수하지만 워커는 재구축이 끝난 뒤 처리한다. 재구축이 끝날 때 버전 충돌로 실패해 전체 임베딩 비용을 버리는 상황을 시작 단계에서 막기 위한 정책이다. 실제 색인 커밋은 게시자 잠금으로 직렬화되므로 커밋에 필요한 Qdrant 작업이 길면 같은 게시자를 쓰는 다른 요청이 기다릴 수 있다. 서로 다른 문서의 준비 이후 활성 버전이 바뀌면 해당 문서의 기존 내용과 임베딩 계약이 변하지 않은 경우에만 최신 버전으로 제한적으로 다시 준비한다. 기존 벡터 캐시를 재사용하고, 동일 문서 충돌 및 연속된 경쟁은 오류로 반환한다.
