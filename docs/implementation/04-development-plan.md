# 검증 및 평가 계획

## 자동 검증

`make check`는 Python 테스트와 정적 검사를 실행한다. 웹 빌드는 `make build`다. 자동 테스트는 가짜 파서·임베딩 서비스와 로컬 Qdrant 등을 이용해 파싱 결과, 재개, 청킹·표, 색인 게시·삭제, 검색·인증과 설정을 검증한다. 실제 공급자와 원격 서버의 사용 가능성이나 검색 품질을 입증하지는 않는다.

변경 시에는 영향을 받는 경로에서 다음을 확인한다.

- 비연속 페이지 누락, 50% 경계, 미수신 결과와 접수 불명 상황에서 불필요한 재전송이 없는가.
- 표 셀·관계와 원문 참조가 청킹·반복 재분할·검색·대화에 이어지고, 축약된 캡션과 제목이 누락되지 않는가.
- 실패 또는 재처리 중 기존 검색 버전과 저장된 결과를 유지하는가.
- 모델·설정 변경 시 해당 계약과 캐시를 올바르게 구분하는가.
- 웹의 설정, 진행·실패·재개 및 iframe 인증이 해당 API와 일치하는가.

## 검색 품질 평가

대상 문서에서 사람이 확인한 질의와 원문 근거를 준비한다. PDF/HWP/HWPX, 스캔 PDF, 보고서 표·도식과 XLSX/PPTX를 실제 사용 비중에 맞춰 포함한다. 같은 문서·모델·버전에서 BM25, Dense, Hybrid와 선택적 재순위를 비교한다. 청크 크기와 겹침을 비교할 때는 나머지 조건을 고정한다.

Hit@k, Recall@k, MRR, 지연을 기록하고 표의 숫자·단위·관계와 인용 정확도는 원문과 대조한다. 의미적 누락, OCR 오류, 파서 구조 오류, 검색 실패를 구분한다. 허용 데이터와 예산을 먼저 정하고 결과·비용·미검증 범위를 함께 기록한다. [평가 입력과 실행](../user-guide/03-integration.md)
