# 처리와 검색 설정

환경 변수는 서버 기본값이다. 웹 설정의 저장값은 환경값보다 우선하며 `DATA_DIR/server-settings.json`에 보관한다. 연결·처리 설정은 진행 중인 문서 처리가 끝난 뒤 저장 즉시 적용된다. 데이터 및 웹 경로와 공개 경로 접두사(`PUBLIC_BASE_PATH`)는 서버 시작 설정으로 관리한다. 문서별 청크·OCR·DPI는 업로드 또는 재처리 때 정한다. 적용된 설정은 작업 기록에 남는다.

## 파서

설정 화면에서 환경 기본 파서와 등록된 파서 중 하나를 선택하고 연결을 추가·수정·삭제할 수 있다. 목록에 저장되지 않은 현재 파서에서 전환할 때는 기존 연결을 목록에 보존한다. 목록의 키는 서버에만 보관한다. 선택한 파서는 새 작업에 적용된다. 대기·진행 중인 작업과 이어서 처리할 작업은 저장된 당시 파서 연결을 사용하며, 작업 상세에 파서 또는 직접 추출 방식을 표시한다. 작업별 연결 정보는 서버에 접근 제한된 파일로 보관하며 API 응답에 키를 포함하지 않는다. 이전 버전에 생성되어 연결 정보가 없고 현재 파서 계약과 일치하지 않는 작업은 원래 파서로 복원할 수 없다.

| 환경 변수 | 기본값 / 역할 |
|---|---|
| `PARSER_PROVIDER` | 코드 기본값 빈 문자열; `.env.example`은 `upstage`. 비우면 문서 처리 비활성화 |
| `PARSER_BASE_URL` | `https://api.upstage.ai/v1`; HTTP 또는 HTTPS 프록시 가능 |
| `PARSER_API_KEY` | 파싱 API 키 |
| `PARSER_MODEL` | `document-parse-260930` |
| `PARSER_MODE` | `enhanced` |
| `PARSER_OPTIONS` | 추가 `key=value` 항목을 세미콜론으로 구분 |
| `MAX_PAGES`, `MAX_RETRY_PAGES` | PDF 최대 2,000쪽, 자동 재시도 최대 200쪽 |
| `PARSER_SYNC_TIMEOUT_SECONDS` | 동기 파싱 요청 900초. PDF 100쪽 이하 및 XLSX·PPTX에 적용. HWP/HWPX는 비동기 처리 |
| `REMOTE_TIMEOUT_SECONDS`, `JOB_TIMEOUT_SECONDS` | 개별 외부 요청 90초, 비동기 작업 대기 900초 |

동기 요청 시간 초과는 접수 여부를 알 수 없으므로 자동 재전송하지 않는다. 파서 또는 프록시 자체의 시간 제한은 별도로 확인해야 한다. 웹에서 저장한 서버 설정은 환경 변수보다 우선하며 저장 직후 적용된다.

추가 옵션은 `coordinates=true;words=false`처럼 지정한다. 빈 값·중복 키·공통 필드(`model`, `mode`, `ocr`, `dpi` 등) 충돌은 거부한다. 세미콜론이 값에 포함되면 전체 항목을 큰따옴표로 감싸고, 큰따옴표는 두 번 써서 이스케이프한다. 키·비밀은 추가 옵션이 아닌 전용 설정에 둔다. 실제 지원 옵션은 파서 API 계약에 따른다.

PDF의 `DEFAULT_OCR_POLICY` 기본값은 `automatic`, `DEFAULT_DPI` 기본값은 미지정이다. DPI는 50–600이며 PDF에만 적용한다. `scanned` 선택과 확정 누락 재시도의 OCR 강제는 선택한 파서가 지원할 때만 적용한다. 지원하지 않으면 실제 요청은 `auto`로 기록하며 그림에서 글자가 없는 이유만으로 동일 요청을 반복하지 않는다. 실제 페이지 미수신은 별도 재시도 규칙을 따른다. DPI는 지원할 때 유지한다.

## 문서 직접 추출

HWP·HWPX·DOCX·XLSX·PPTX는 업로드 또는 **문서 다시 읽기**에서 다음 방식을 선택할 수 있다. 기본 API 값 `extraction_mode=parser`는 선택한 파서에 원본을 보낸다. 선택한 파서가 해당 형식을 지원하지 않을 때 웹은 직접 추출 방식을 선택한다.

- `native_text`: 원본에서 읽을 수 있는 내용을 추출한다. 삽입 이미지는 분석하지 않으며 누락 경고와 일부 처리 상태로 표시한다.
- `native_visual`: 직접 추출에 더해 삽입된 PNG/JPEG 이미지를 순서대로 PaddleOCR-VL에 전달한다. 이미지별 결과는 원본 본문과 구분해 저장한다. 다른 파서의 이미지 호출은 아직 지원하지 않는다.

XLSX 직접 추출은 원본 주소, 타입이 있는 값, 수식, 저장된 계산값, 표시 형식, 스타일과 병합 관계를 보존한다. 캐시가 비어 있는 수식은 **계산값 없음**으로 표시한다. 단순 날짜 마스크와 0 채움 정수 마스크는 표시용 값에 반영한다. 복합 표시 형식은 표준화된 값으로 표시하며, Excel 표시 형식과 원본 값은 구조 결과에 함께 보존한다. 각 청크에는 실제 포함된 셀 주소를 기록한다. HWPX는 본문·표 및 삽입 이미지를 처리하며 쪽 배치와 도형 관계는 보장하지 않는다. HWP는 pyhwp의 구조 XML에서 구역·문단의 원본 개요와 목록 속성, 표 셀·병합 범위, 캡션과 그림의 원본 참조를 추출한다. 그림이 연결된 문단과 객체의 상대 좌표·자르기 값은 보관하지만 편집기의 실제 페이지 배치는 복원하지 않는다. 원본 연결을 확인하지 못한 첨부 이미지는 별도로 보존하고 경고한다. PPTX는 슬라이드의 텍스트·표와 이미지를 처리하되 배치·연결 관계 및 노트는 보장하지 않는다. 차트 미리보기 생성 실패, 중첩 표, 지원하지 않는 이미지 등은 경고한다. 이러한 미처리 범위가 있으면 일부 처리로 표시하고 기존 검색 결과를 보호한다.

DOCX는 본문 블록·표 및 삽입 이미지를 추출한다. 표 병합 관계와 페이지 배치는 확인 필요로 남기며 머리글·바닥글과 도형 관계는 보장하지 않는다. 직접 추출한 이미지 원본은 분석 여부와 무관하게 작업별 해시 식별자로 저장한다. 다시 청킹하는 작업에는 이미지도 복사하여 기준 작업 삭제의 영향을 받지 않게 한다. 기존 작업은 새 기능 적용 전에 보존한 이미지가 없을 수 있으며 이미지를 새로 추출하려면 원본부터 다시 읽어야 한다.


**설정 → Excel 구조 분석**에서 시트의 외부 모델 분석을 켤 수 있다. 기본값은 꺼짐이며, 외부 처리 허용과 LLM API 연결도 필요하다. 분석 요청에는 미확정 시트의 셀 주소·값·수식, 병합 정보와 병합 내부 값이 포함된다. 구조 모델을 비우면 기본 대화 모델을 쓴다. 기본 한도는 통합 문서당 3회, 시트당 셀 입력 64,000바이트, 생성 4,096토큰, 요청 시간 20초다. 이미 검증한 동일 요청은 내용과 모델·프롬프트·스키마·구조 버전이 일치할 때 로컬 캐시에서 재사용한다. 한도 초과, 연결 실패 또는 검증 실패 시에는 로컬 구조가 유지되며 시트의 검토 화면에 상태가 표시된다.

이미지 요청별 시작과 완료 결과를 저장한다. 중단 후 완료 결과는 재사용하고, 시작됐지만 완료 여부를 알 수 없는 요청은 자동 재전송하지 않는다. Paddle 이미지 요청은 기본 90초(동기 요청 상한이 더 작으면 그 값)이며 파서 추가 옵션 `image_timeout_seconds=초`로 변경할 수 있다. 이미지 요청이 실패하거나 응답을 확인하지 못하면 이후 이미지 요청을 중단하고 이미 추출한 본문과 모든 이미지 원본을 검토 단계로 넘긴다. 서버가 중단되더라도 시작만 기록된 이미지는 재전송하지 않고 본문·이미지 복구를 재개한다. 이미지 분석 실패가 다른 이미지나 전체 본문의 분석 완료를 뜻하지 않는다. 이미지 100개, 이미지당 20 MiB·합계 100 MiB 및 XLSX 시트 5,000행·100열·25,000칸 제한이 있다. 제한 초과나 추출 실패 시 조용히 잘라내지 않고 실패한다. 전체 페이지 시각 분석과 자동 OCR 보완은 아직 제공하지 않는다.

단일 프레임 BMP·GIF·WebP·TIFF 이미지는 원본을 유지하면서 OCR 요청에만 PNG로 변환한다. 여러 프레임이나 안전 한도를 넘는 이미지는 건너뛰고 확인이 필요하다. 완료 여부가 불명확한 이전 이미지 요청은 자동 재전송하지 않는다.

미게시 작업의 이미지 목록에서는 확인이 필요한 이미지를 분석, 원본만 포함, 분석과 원본 포함, 검색 제외, 원본과 설명 직접 입력 중 선택한다. 처리된 이미지와 선택 결과도 전체 이미지 보기에서 확인할 수 있다. 분석 요청은 작업에 저장된 파서 설정을 사용한다.

원본만 포함은 기존 본문과 이미지의 관계를 이용해 검색 결과에 이미지를 보여주는 방식이다. 검색할 본문과 연결되지 않은 단독 이미지는 직접 설명을 입력해야 한다. 설명은 사용자가 작성한 검색 텍스트로 저장되고 원본 이미지와 연결되며 이미지 자체를 임베딩하지 않는다. 분석과 원본 포함은 분석 텍스트와 원본을 함께 제공한다. 검색 제외는 검색 결과에서 이미지와 분석을 제외하되 원본은 보존한다. 위치 관계가 미확인이거나 추정된 경우 확정 관계로 표시하지 않는다.

미게시 작업에서 선택한 결과는 같은 작업에 병합하며 새 검색 버전은 게시 시점에 생성한다. 미처리 항목이 남으면 게시할 수 없다. 처리에 실패하면 변경 전 산출물을 복원한다. 이미 게시된 작업에 대한 변경은 새 미게시 작업에서 처리하므로 기존 검색과 근거는 보존된다. 단독 이미지 설명은 사용자가 작성한 내용이며 원본 내용을 자동 검증하지 않는다.

PaddleOCR-VL의 이미지 블록 글자 인식은 파서 추가 옵션에 `useOcrForImageBlock=true`로 요청할 수 있다. 생략하면 서버 설정에 따르며 PaddleOCR 문서의 초기 기본값은 `false`다. 인식 비용과 품질은 서버·문서에 따라 달라진다. 글자 없는 이미지 블록은 내용 확인이 필요하다고 안내하되, 정상 수신된 문서 전체를 자동으로 미완료 처리하지 않는다. 글자 없는 이미지만 있는 스캔 페이지 등 실제 누락 가능성이 확인되면 별도로 검토한다. [PaddleOCR-VL 공식 문서](https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/PaddleOCR-VL.html)

새 청킹은 `structure-v11`로 기록된다. 기존 검색 버전은 변경되지 않는다. 저장된 파싱 결과로 청킹부터 다시 처리하면 새 청킹 규칙이 적용된다. Paddle 표 응답의 리터럴 `\\n` 정리는 어댑터 처리이므로 이미 저장된 응답에 적용하려면 다시 파싱해야 한다.

직접 추출에서 DOCX의 제목 스타일·개요 수준과 HWPX의 개요 문단 속성을 제목 수준으로 사용한다. 제목 스타일이 사용된 DOCX/HWPX에서는 일반 번호 문단을 제목으로 추정하지 않는다. 제목 스타일을 찾지 못한 경우 마침표로 끝나는 번호 표식이 있고 본문 목록으로 확인되지 않은 짧은 문단만 제한적으로 제목으로 추정한다. 인접한 번호 문단과 원본에서 목록으로 표시한 문단은 목록·본문으로 보존한다. `1.2 내용`처럼 소수와 구분할 수 없는 줄은 제목으로 추정하지 않는다. HWP는 원본 문단의 개요 수준을 사용하고 번호 문자열만으로 제목을 추정하지 않는다. 원본에서 개요 스타일을 쓰지 않은 문단은 본문으로 남는다. 자동 개요·목록 번호의 화면 표시 형식은 재현하지 않는다. DOCX·HWPX의 명시된 표 머리글을 사용하고, 일반 셀만 있는 표의 첫 행은 조건이 맞을 때 미검증 열 제목으로 추정하되 원본 셀을 보존한다.

형식의 일반적인 추출 한계는 안내로 표시하고, 실제 미처리·미확인 항목은 별도 경고와 검토 상태로 표시한다. 이미지 경고는 대상 이미지가 모두 처리되었을 때만 해제한다. 이미 저장된 파싱 산출물에는 새 제목 추출이 소급 적용되지 않으므로 원본부터 다시 읽어야 한다.

PPTX 슬라이드의 제목 자리표시자는 제목으로 유지하고, 같은 텍스트 상자의 연속 문단을 크기 제한 내에서 묶는다. 다른 상자는 자동으로 합치지 않는다. `structure-v11`는 청크를 만드는 규칙의 식별자로, 검색 버전이나 사용자 문서 버전과 별개다. 해당 규칙을 기존 문서에 적용하려면 저장된 파싱 결과로 다시 청킹하고 새 검색 버전을 게시한다. PPTX 제목 자리표시자와 직접 추출 제목 판별 변경을 적용하려면 원본부터 다시 읽어야 한다.

파서가 모든 제목에 같은 수준을 부여한 경우 장·번호 구조는 원본의 명시된 제목을 우선하고, 인식 가능한 번호 계층만 보수적으로 추정한다. 번호 없는 제목은 문맥을 사용하되 추정으로 표시하며, 다음 번호 제목에서 기존 번호 경로를 복원한다. 제목 수준에 근거가 없으면 정확한 계층을 보장하지 않는다.

HWP 직접 추출은 `hwp5proc xml`을 사용한다. 표 셀·개요·목록과 그림 참조는 파서 구조를 사용하며 쪽 번호를 생성하지 않는다. 표 캡션과 이미지 원본을 보존한다. 복구하지 못한 도형·중첩 객체는 경고하고 그림의 위치 관계는 문단 단위 미검증 관계다. `hwp5proc`이 실패하면 텍스트 추출로 조용히 대체하지 않고 오류를 표시한다. 기존 HWP 파싱 결과에 이 구조를 적용하려면 원본부터 다시 읽어야 한다.


검색 후보 수는 기본 25개이고 1~100 범위에서 설정한다. 리랭킹 결과 수는 기본 5개이며 검색 후보 수 이하로 설정한다. 리랭킹을 사용하면 후보를 재정렬한 후 설정된 결과 수 이내를 반환한다. 사용하지 않으면 검색 후보 순서로 반환한다. 검색 요청의 표시 수는 최종 상한이며 생략 시 검색 API는 5개, 대화는 최대 20개다. 대화 근거는 항목당 4,096바이트와 전체 32KiB 예산을 적용한다. 검색 응답의 search_counts에는 후보·리랭킹·반환 수가 기록된다. 설정 변경은 재색인을 요구하지 않는다.
