# 남은 개선 과제

현재 코드 이슈의 판정, PoC 수정 순서와 항목별 방향은 [코드 이슈 검토](09-code-issue-review.md)를 따른다. 아래는 PoC 이후로 미루거나 실험 후 결정할 과제다. 완료된 기능 목록이 아니다.

## 검색 품질과 평가

- 원문 근거가 있는 한국어 질의셋을 만들고 BM25·Dense·Hybrid, 선택적 재순위를 비교한다. 표의 숫자·단위·헤더 관계, 도식과 스캔 문서를 별도로 평가한다.
- 청크 크기·겹침과 문맥 확장에 따른 검색률, 중복, 지연 및 비용을 측정한다. 기본값은 검증된 최적값이 아니다.
- 한국어 토큰화와 파서 오류, 검색 실패, 답변·인용 실패를 구분해 분석한다. [평가 계획](04-development-plan.md)

## 구조·출처 보강

- 파서가 알려주지 않는 Excel 시트·셀, PPT 슬라이드와 검색 요소 간 대응을 검증 가능한 방식으로 연결한다. 위치가 불확실하면 추정 결과로 구분한다.
- 페이지 경계의 표 연속성, 복잡한 병합 셀, 캡션·단위·주석 관계를 다양한 문서에서 검증하고 필요한 경우 보강한다. 각주와 목차를 일괄 제외하지 않으며 별도 처리의 필요성을 평가한다.
- 수준 정보가 단일 단계인 실제 파서 응답에서 숫자 제목 계층 추정의 정확도를 검증한다. 추정 결과는 원본 구조와 구별한다.
- 도식의 연결선과 관계를 다루는 선택적 시각 분석을 검토한다. 원문과 모델 추정을 분리하고 정확도·비용을 평가한다.
- 원본과 파싱 결과의 의미적 누락 판단을 별도로 설계한다. 현재 페이지·텍스트·셀 비교는 의미 일치 여부를 보장하지 않는다.

## 확장과 운영

- XLSX·PPTX의 비동기 파싱 지원과 원본 시트·슬라이드에 대한 처리 범위 검증은 공급자·프록시 계약 확인 후 검토한다.
- 공급자별 파서 기능·설정 검증 계약을 정리하고 다른 API 방식의 어댑터로 확장성을 검증한다. 현재 등록된 실제 파서는 Upstage다.
- 모델·토크나이저·입력 한도를 신뢰할 수 있게 확인할 수 있는 어댑터에 한해 토큰 기준 검사를 선택적으로 검토한다. 모르는 한도는 임의로 정하지 않는다.
- 실제 연결 환경에서 문서 유형별 파싱·재개·검색과 iframe 삽입을 확인한다. 다중 사용자 권한 분리, 분산 작업, 장애 복구·관측 및 데이터 보존은 운영 요구에 따라 별도 설계한다.

## 작업 안전성과 복구

- 작업 전체 잠금을 줄이고 동시 변경 시 상태·버전 일관성을 보장한다. 검색과 삭제의 동시성 및 게시 단계의 잠금도 운영 요구에 맞춰 개선한다.
- 작업 FIFO, 워커 생존 감시, 비동기 재구축과 색인 재개를 설계한다. 장시간 요청 중 끊김과 중복 실행에 대한 상태를 제공한다.
- 원격 파싱의 배치 다운로드에 전체 기한을 적용하고, 공급자·프록시별 만료 응답 계약과 재시도 계획·접수 불명에 대한 복구를 검증한다. 확정된 추가 누락에 대한 별도 시도와 비용 기록을 검토한다.
- 전체 재파싱에서 기존·신규 페이지 결과의 품질과 비용을 비교하고 선택 정책을 검증한다. 다른 문서의 게시가 검토 중인 문서 적용을 불필요하게 막지 않도록 문서 단위 충돌 검사를 검토한다.
- 검색 버전의 중복 파일 읽기를 줄이고, 개정판 교체 흐름을 설계한다.

## 검색 버전과 비용

- 표현 버전 변경 시 기존 파싱 결과를 활용한 일괄 재청킹·재색인과 진행·실패 복구를 제공한다.
- 검색 버전 및 관련 작업의 보존·삭제 정책을 정하고, 캐시 전체 삭제 없이 문서별 삭제가 가능한지 검토한다.
- 프로필별 색인 상태와 모델 변경 전환을 개선한다. 프로필별 수동 재구축은 지원한다. 같은 주소나 모델명만으로 임베딩 공간의 동일성을 가정하지 않는다.
- 미사용 함수는 호출 여부와 재사용 가능성을 확인한 뒤 정리한다.
