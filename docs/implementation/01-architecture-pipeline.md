# 아키텍처와 처리 흐름

## 구성

FastAPI가 정적 웹, API, 인증과 단일 백그라운드 작업자를 제공한다. LangGraph가 검사·파싱·품질 확인·검색 표현·임베딩·색인 노드를 연결한다. 대화의 검색과 답변 연결은 LangChain Core를 사용한다. `DATA_DIR` 잠금으로 하나의 데이터 디렉터리를 두 서버가 동시에 쓰지 못하게 한다.

| 모듈 | 책임 |
|---|---|
| `apps/api` | 인증, 입력 검증, API, 작업자와 정적 UI |
| `parsing` | 파서 설정·등록·공통 요청/결과·Upstage 어댑터 |
| `ingestion_graph`, `ingestion_service` | 작업 단계, 상태, 재개, 산출물 보관 |
| `inspection`, `office_inspection` | PDF 페이지 검사와 Office 원본 정보 검사 |
| `chunking`, `structure_relations` | 원문 요소, 표·캡션 관계, 검색 청크 |
| `embedding_profiles`, `embedding_adaptation` | 모델 설정·입력 분할·벡터 재사용 |
| `index_publication`, `search_engine`, `published_retrieval` | 검색 버전 게시, 검색 방식 결합, 근거 복원 |
| `chat` | 검색된 근거를 사용한 답변 |
| `apps/web` | 문서 관리, 검색, 대화, 설정 및 iframe UI |

## 작업과 복구

1. 파일 확장자·서명·크기와 Office 압축 범위를 검사하고 원본을 보관한다.
2. 문서 프로필을 선택하고 원본 페이지 또는 Office 구조를 검사한다.
3. 파서에 요청하고 결과·접수 정보·장문 배치를 저장한다. HWP/HWPX와 PDF 100쪽 초과는 Upstage 비동기 경로를 사용하며 현재 어댑터의 최대 PDF 페이지는 2,000쪽이다. 서버 제한이 더 작으면 그 제한이 우선한다.
4. PDF의 확정 누락과 미수신 결과를 구분한다. 확정 누락이 전체의 50% 이하면 부분 재파싱, 초과면 전체 재파싱이다. 전체 재파싱 조건에서 미수신 결과가 있으면 이를 먼저 확인한다. `MAX_RETRY_PAGES` 또는 파서의 부분 처리 지원 범위를 넘으면 남은 범위를 표시한다.
5. 저장된 요소로 검색 청크를 만든다. 누락이나 확인할 이미지가 있으면 게시 전 검토 상태로 멈춘다. 이미지 선택은 같은 미게시 작업에 병합한다. 사용자가 검토를 마치고 게시하면 임베딩과 색인을 준비해 새 검색 버전을 확정한다. 검토할 사항이 없는 결과는 자동 게시한다.

접수 기록이 있는 미수신 결과는 기존 요청을 조회한다. 공급자가 종료·취소로 확정해 더 받을 수 없는 범위와 일시적인 배치 다운로드 실패를 구분한다. 이미 게시된 작업을 이어서 처리할 때는 요청 기록과 기존 결과를 새 작업으로 복사해 원래 작업과 검색 근거를 보존한다. 재시도 결과를 저장하고 재개 시 재사용한다. 접수 여부가 불명확하고 요청 ID가 없으면 자동 재전송하지 않는다. 임베딩·색인 단계에서 중단되면 저장된 청크와 캐시로 재개한다. 그래프 상태 자체의 영속 체크포인터는 사용하지 않는다.

페이지 누락 또는 기존 검색 요소의 단어·셀·행 관계 감소가 발견되면 신규 문서도 미게시 상태로 두고, 기존 검색 버전이 있으면 유지한다. 내용 차이는 사용자가 비교하고 적용할 수 있으나, 미수신·누락 페이지가 남은 작업은 이 확인만으로 적용할 수 없다. 이 비교는 원본의 의미를 판정하지 않는다.

## 검색 표현

제목 경로와 같은 페이지 또는 확인 가능한 직접 추출 문서 구역의 인접 본문·목록을 크기 내에서 묶는다. 페이지가 없는 HWP는 구역과 문단 순서, DOCX는 문서 순서와 제목을 사용하며, HWP/HWPX 구역·PPTX 슬라이드·XLSX 시트 경계를 넘지 않는다. 위치 근거가 없는 외부 파서 요소는 무조건 같은 구역으로 묶지 않는다. 원본 쪽 번호를 임의로 부여하지 않는다. 매뉴얼은 목록을 주변 본문과 분리하고, 표 중심은 표 행을, 슬라이드 중심은 요소를 구분한다. 긴 본문만 설정된 겹침으로 분할한다.

표 셀과 머리글·병합 범위의 가용 정보를 보존한다. 인접 캡션과 조건이 일치하는 다음 페이지 표는 추정 관계로 연결한다. 이미지와 도식은 파서가 제공한 텍스트·대체 텍스트를 사용하며 화살표 등의 관계는 생성하지 않는다. 검색 시 같은 페이지와 제목의 인접 본문을 각 최대 600자까지 문맥으로 제공한다.

직접 추출한 삽입 이미지는 작업별 원본 바이트와 이미지 요소로 보관한다. 이미지 OCR 결과는 같은 이미지의 분석 결과로 연결한다. HWP·HWPX·DOCX는 같은 원본 문단의 이미지와 텍스트를 연결하고, PPTX는 회전·그룹 변환이 없는 객체 중 슬라이드 좌표상 가까운 이미지가 하나로 구분될 때만 위치 관계를 추정한다. XLSX는 이미지 앵커와 검색된 표 셀 위치가 가까운 경우만 연결한다. 위치가 같거나 가깝다는 것이 의미적 관계를 증명하지 않으며 원본 참조가 없는 HWP 첨부 이미지의 본문 위치는 미확인이다. 검색 시 연결된 이미지와 별도 OCR 청크를 제한적으로 반환하며 위치 기반 관계는 미검증으로 전달한다.

병합 셀로 구분된 표 구역에서 파서가 열 제목을 일반 셀로 반환한 경우, 동일 구역 첫 행의 짧고 서로 다른 셀과 아래 셀의 열 좌표가 일치할 때 열 제목을 추정해 검색 표현에 포함한다. 추정은 `label_origin=inferred`와 `quality=unverified`로 남기며 모든 표의 관계를 복원한다고 보장하지 않는다. 검색은 상위 표 결과 하나의 동일 문서·작업·원본 표 요소에 속하는 청크를 최대 3개, 9,000자 범위에서 추가 근거로 제공한다. 첫 결과가 제목·본문이고 같은 페이지와 제목 요소 아래 원본 표가 하나뿐일 때도 적용한다. 다른 표와 페이지의 추정 이어짐을 자동 근거로 합치지 않는다. 누락된 분할 청크가 있으면 완전하지 않음을 대화에 전달한다.

파일 형식별 프로필과 원본 위치는 별개다. Excel 시트·수식 및 PPT 슬라이드·노트 유무를 원본에서 검사하지만, 파서 페이지에 자동 대응하지 않는다. 파서가 명시한 시트·셀 또는 슬라이드 위치만 원본 목록과 대조하고 미검증 출처로 표시한다.

이미지별 미게시 변경은 동일 작업의 산출물에 적용하며 실패 시 변경 전 산출물을 복원한다. 이미 게시된 작업을 수정할 때는 새 작업으로 분기한다. 사용자가 작성한 이미지 설명은 검색 가능한 텍스트이며 원본 이미지에 직접 연결된다. 원본 이미지 자체는 벡터 검색하지 않는다.

단계가 모두 같은 제목에서 번호로 경로를 보완할 때 번호 없는 제목 및 `1)`, `가.` 항목은 기존 번호 경로를 보존하는 추정으로 처리한다. 로마 숫자는 유효한 표식만 장으로 해석하고, 연도 제목은 문서 첫 제목이거나 파서가 문서 제목으로 명시한 경우에만 최상위로 취급한다. 실제 제목 수준은 모호할 수 있으며 파서의 명시적 다단계 제목은 우선한다. Paddle 및 직접 추출 표의 단순 첫 행은 조건이 맞을 때에만 열 제목으로 추정하고 원래 셀도 보존한다. 추정은 미검증으로 표시한다.
