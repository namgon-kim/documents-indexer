# 웹 사용법

## 문서 등록

1. **문서 관리**에서 PDF, HWP, HWPX, DOCX, XLSX 또는 PPTX를 선택하거나 끌어놓는다. 기본 파일 크기 제한은 50 MiB다.
2. 사용할 임베딩 모델과 문서 처리 유형을 선택한다. XLSX와 PPTX는 자동 선택 시 각각 표 중심과 슬라이드 중심을 사용한다.
3. 필요한 경우 **고급 처리 설정**에서 청크 크기·겹침과 PDF DPI를 바꾼다. 스캔 PDF 유형은 OCR을 강제한다.
   HWP·HWPX·DOCX·XLSX·PPTX는 **문서 읽기 방식**에서 파서, 빠른 직접 추출, 직접 추출과 이미지 분석을 선택할 수 있다. 이미지 분석은 현재 PaddleOCR-VL 연결이 필요하다. 빠른 처리에서 분석을 생략한 이미지도 보존하며, 직접 추출로 다루지 못한 구조는 작업 상세에 표시한다.
4. **업로드 및 처리**를 누르고 문서 카드에서 문서 입력, 읽기, 누락 확인, 내용 정리, 임베딩, 검색 준비 상태를 확인한다.

같은 파일이 이미 있으면 기존 문서를 확인하거나 **새 문서로 추가**를 선택할 수 있다. 새 문서로 추가하면 파싱 비용과 검색 결과가 중복될 수 있다.

겹침은 긴 본문을 나눌 때 앞뒤 청크에 반복하는 문자 수다. 각 청크에 무조건 적용되지는 않는다. 화면의 진행률은 단계별 구간과 확인된 처리량을 조합한 값이다.

## 상태와 다시 처리

문서 카드에서 **처리 상세 및 작업 관리**를 열어 작업 기록, 누락과 미수신 페이지, 원본 시트·슬라이드 정보 및 처리 설정을 확인한다.

| 상태 | 의미와 행동 |
|---|---|
| 대기·처리 중 | 처리 단계와 가용한 진행량을 확인한다. |
| 검색 가능 | 검색과 대화에서 해당 문서를 사용할 수 있다. |
| 일부 처리 | 미게시 검토가 필요하거나, 확인한 일부 결과가 게시된 상태다. 작업 카드에서 게시 여부와 확인할 내용을 확인한다. |
| 처리 실패 | 오류를 확인한다. 이어서 처리 가능한 작업은 해당 버튼을 사용한다. |

글자 없는 그림·도식은 빈 페이지로 확정하지 않는다. 누락 확인이 필요한 새 결과는 검색에 게시되지 않으며, 기존 검색 버전이 있으면 유지된다. 확인할 이미지의 처리 방식을 모두 선택하고 누락 범위를 확인한 뒤 **검토 완료 · 게시**를 선택한다. 미수신 페이지가 남아 있다면 확인된 범위만 게시하는 결정이다. 이미 게시된 결과를 변경하면 새 작업으로 진행해 이전 검색 근거를 보존한다.

외부 파서로 처리한 HWP/HWPX의 페이지 수는 원본 편집기의 쪽 번호와 다를 수 있다. 미수신 페이지는 가능한 경우 **이어서 처리**로 기존 요청에서 다시 확인한다. 원격 작업이 종료됐거나 요청 완료 여부가 불명이면 안내를 확인한다.

작업 상세의 **추출 이미지 목록 보기**에서 이미지별 처리 방식을 선택한다. 검토 중에는 확인이 필요한 이미지가 먼저 보이며 처리 완료 이미지도 볼 수 있다.

- **이미지 분석**: 선택한 이미지만 분석해 얻은 텍스트를 검색에 사용한다.
- **원본만 포함**: 연결된 본문이 검색되면 원본 이미지를 함께 보여준다. 이미지 자체는 검색하지 않는다.
- **분석과 원본 포함**: 이미지 분석 텍스트와 원본을 함께 사용한다.
- **원본과 설명 직접 입력**: 본문과 연결되지 않은 이미지에 검색할 설명을 직접 작성한다. 설명이 검색되면 원본을 보여준다.
- **검색에서 제외**: 이미지와 분석을 검색에서 제외하며 원본은 보존한다.

선택한 내용은 같은 미게시 작업에 반영된다. 게시하기 전에는 검색 버전이 생성되지 않는다. 이미지 처리에 실패하면 이전 검토 결과가 유지된다. 이미지의 위치 관계가 확인되지 않았다면 원문 위치를 단정하지 않는다.

새 결과에서 기존 검색 내용의 감소가 확인되면 기존 버전을 유지한다. **이전·새 내용 비교**에서 페이지별 본문과 표 셀을 확인하고, 의도된 변경이면 **확인한 새 내용 적용**을 선택한다. 이 비교는 파싱 결과 간 차이이며 원본의 정답을 자동 판정하지 않는다.

작업 기록 또는 문서를 삭제할 수 있다. 문서 삭제는 서버 원본과 해당 문서의 모든 검색 버전 데이터를 대상으로 한다. 별도 백업, 스냅샷 및 외부 서비스 결과는 포함하지 않는다.

## 검색과 대화

**문서 검색**에서 검색어를 입력한다. **검색 조건**에서 임베딩 모델, BM25·Dense·Hybrid, 재순위, 결과 수, 검색 버전과 문서를 선택할 수 있다. 검색 결과의 **근거 원문 보기**, **문맥 원문 보기**와 **앞뒤 문맥 보기**로 관련 내용을 확인한다. 제목 계층이나 표 관계가 추정이면 확인이 필요하다. 색인과 모델 계약이 다른 이전 버전은 BM25로 검색하며, Dense 검색에는 해당 모델의 색인을 다시 준비한다. 검색 결과의 시트·셀 또는 슬라이드 위치는 파서가 명시한 경우에만 미검증 출처로 표시된다.

**문서 대화**에서 질문하면 검색된 문맥을 바탕으로 답변한다. 답변의 번호 또는 근거 목록에서 관련 검색 결과와 파싱 원문을 열 수 있다. 검색 범위에서 문서·모델·방식·버전을 고른다. 검색된 문서 내용과 대화가 답변 모델로 전송되고, 대화 기록은 현재 브라우저 탭에 보관된다. Enter는 전송, Shift+Enter는 줄바꿈이다.

**설정**에서 연결과 기본값을 관리한다. 답변 모델·추론 수준은 대화 모델 영역에서 선택하고, 임베딩 모델은 청크·임베딩·벡터 DB 영역에서 관리한다. 환경 변수는 기본값이고 저장한 서버 설정이 우선한다. 연결과 처리 설정은 진행 중인 문서 처리가 끝난 뒤 적용된다.

## Qdrant 확인

색인 게시 시 `ingestion_<하이픈 없는 검색 버전 UUID>` 컬렉션이 생성된다. `GET /v1/ingest-index-versions`에서 버전을 확인하고 Qdrant 대시보드의 Collections에서 컬렉션을 확인할 수 있다. Qdrant에 저장된 벡터 외에 서버의 원본, 작업, 청크 및 BM25 데이터도 보관해야 검색을 복원할 수 있다. [저장과 백업](01-setup-build.md)


## Excel 구조 검토와 전체 표 조회

- 기존 XLSX 작업에 새 구조를 적용하려면 **문서 다시 읽기**에서 직접 추출을 선택한다. 새 작업이 게시되면 해당 문서의 현재 검색 버전이 갱신되며 이전 게시 버전은 계속 선택할 수 있다.
- 작업 상세의 **Excel 구조 검토**에서 시트, 원본 셀, 병합 내부 값과 미확정 영역을 확인한다. 표 범위와 제목·헤더를 편집하고, 빠지는 원본 셀에는 검색 제외 이유를 입력한다. 저장은 수정한 시트의 구조를 새 작업에서 검증하고 색인한다. 기존 이미지 추출과 분석 결과도 재사용한다.
- **문서 대화**에서 XLSX 문서를 한 개 선택한 뒤 **검증된 Excel 표 전체에서 개수·분포·날짜 범위 조회**를 켠다. 모델이 질문을 표와 조건으로 변환하면 서버가 전체 데이터 범위에 적용한다. 응답에는 범위, 적용 조건과 계산값 누락 등으로 인한 불완전성이 표시된다.
